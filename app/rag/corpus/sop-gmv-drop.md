# SOP：GMV 下滑归因分析

适用场景：用户反馈「GMV 跌了 / 销售额下滑 / 上个月成交额不如前一个月」。
目标：定位下滑主要来自哪个维度，给出有数字支撑的结论，不猜测。

## 第一步：确认口径与事实

1. 先对齐口径：GMV = 已完成订单金额（status='completed'），时间左闭右开。
2. 取近 6~12 个月 GMV 月度序列，确认「下滑」是真实趋势还是单月波动。
   - 用 date_trunc('month', created_at) 或 strftime(created_at,'%Y-%m') 按月聚合。
   - 单月环比下降 < 5% 通常在正常波动范围内，先声明再继续。

## 第二步：乘法拆解

GMV = 订单量 × 客单价。分别取两个指标的月度序列，判断下滑主要由谁贡献：

- 订单量跌、客单价稳 → 流量或转化问题，转第三步 A。
- 客单价跌、订单量稳 → 结构问题（品类/单价），转第三步 B。
- 双跌 → 先看是否有大促基数或整体性问题，转第三步 C。

## 第三步：维度下钻（一次只动一个维度）

A. 流量/转化路径：按渠道（channels）拆订单量——iOS / Android / 小程序 / Web / H5
   哪个渠道掉了；再看该渠道付费用户数（COUNT(DISTINCT user_id)）是否同步下滑。

B. 品类结构：关联 products + categories，按类目拆 GMV 与订单量，
   找出贡献下滑额最大的 1~2 个类目；对比类目客单价变化。

C. 基数效应：对比去年同期（若有数据）与上月是否有大促（双 11 / 618 权重月），
   区分「高基数回落」与「真实下滑」。

## 第四步：异常排查

- 状态结构变化：按 status 拆订单数，看 refunded/cancelled 占比是否异常升高。
- 地区异常：按 regions 拆 GMV，确认不是单一地区掉量拖累全局。

## 输出要求

- 结论格式：先一句话结论（下滑幅度 + 主因维度），再给拆解表格。
- 每个数字标注口径（时间范围、status 过滤）。
- 数据不足（时间范围无数据）时如实说明，禁止编造。
