# 技能：RFM 用户分层

适用场景：「做个 RFM 分析 / 用户分层 / 找出高价值用户」类问题。
目标：用订单数据把用户分成有运营含义的层级，每个数字可溯源，不拍脑袋。

## 执行步骤

1. 明确窗口与口径：默认近 12 个月、status=completed；假设要声明，别默默换口径。
2. 算三维（delegate_sql，orders 表 GROUP BY user_id）：
   - R（Recency）：最近一次 completed 订单距今天数 = 当前日期 - MAX(created_at)。
   - F（Frequency）：窗口内 completed 订单数 = COUNT(*)。
   - M（Monetary）：窗口内累计消费 = SUM(amount)。
   - 同时取整体均值：AVG(R)、AVG(F)、AVG(M) 作为「高/低」的分界参考。
3. 高低分界：R ≤ 30 天为「高」（越近越好），F ≥ 2 为「高」，M ≥ 全体用户均值（或中位数，注明用了哪个）为「高」。
4. 归入 8 分格（R高F高M高=重要价值用户 … R低F低M低=流失边缘用户），
   用一条 SQL 或分步查询数出每层人数与占比。
5. 结论：指出占比异常的层（如「重要挽留用户占 30%」），每层给 1 条可执行建议。

## 8 分格速查

| R | F | M | 层级 | 运营动作 |
|---|---|---|---|---|
| 高 | 高 | 高 | 重要价值用户 | VIP 服务、优先权益 |
| 高 | 高 | 低 | 潜力用户 | 客单价提升（组合购/满赠） |
| 高 | 低 | 高 | 重要发展用户 | 提频（复购券、周期购） |
| 高 | 低 | 低 | 新用户 | 新客引导与首购后激励 |
| 低 | 高 | 高 | 重要挽留用户 | 召回（定向优惠、回访） |
| 低 | 高 | 低 | 一般保持用户 | 低成本触达 |
| 低 | 低 | 高 | 重要深耕用户 | 唤醒高价值沉睡客 |
| 低 | 低 | 低 | 流失边缘用户 | 观察或放弃，别乱花钱 |

## 常见陷阱

- 窗口不声明：12 个月和 3 个月的分层结果完全不同，结论必须带窗口口径。
- PII 红线：聚合到 user_id 可以，任何情况下不许 SELECT 手机号等 PII 字段。
- 新客误判：注册晚的用户天然 F=1、R 小，是「新用户」不是「低价值」，看 R 区分。
- 只给分格不给动作：RFM 的价值在运营建议，分表只是中间产物。

## 输出要求

- 分层结果表：每层人数、占比（引用口径：窗口、completed 过滤）。
- 每层 1 条运营建议，动作要具体到「发什么、给谁」。
- 标注「高/低」分界用的是均值还是中位数。
