# SOP：退款率异常排查

适用场景：「退款率怎么变高了 / 退款异常 / 退单太多」类问题。
目标：定位退款抬升的来源（品类/渠道/时段/金额段），区分真实质量问题和统计口径问题。

## 口径先行

- 退款率 = 已退款订单金额 / **全部状态**订单金额（refund_rate，required_filters 为空）。
- 千万不要给退款率加 status='completed' 过滤——那会把分母算错。
- 金额口径 vs 笔数口径：按金额和按订单笔数算出的退款率可能方向不同，先声明用哪个。

## 排查步骤

1. 趋势确认：按月取退款率序列（3~12 个月），确认是真异常还是正常波动。
   电商退款率通常有个位数到 10%+ 的波动带，单月 +1~2 个百分点先不叫异常。
2. 分母结构：退款率抬升可能不是退款变多，而是分母（总 GMV）回落——
   大促后基线回落会自然推高退款率，先对比分子分母各自的环比。
3. 维度下钻（一次一个维度）：
   - 品类：orders JOIN products JOIN categories，按类目算退款率，找异常类目。
   - 渠道：按 channels 拆，确认是否某端活动引流带来的低质量订单。
   - 时段：按周/日看退款集中点，对应促销结束日（冲动消费退单潮）。
   - 金额段：amount 分桶（<100 / 100-300 / 300+），低价单退款率天然偏高。
4. 交叉验证：异常维度里再按 status 结构看 refunded 订单数的绝对量，
   排除小基数造成的比率虚高。

## 输出要求

- 结论模板：退款率从 X% 升到 Y%（时间范围），主因是【维度】的【具体值】，
  分子/分母贡献各占多少。
- 图表：退款率趋势折线 + 异常维度对比柱状图。
- 提醒：如需用户级退款明细，phone/email 等 PII 字段禁止查询，改用聚合。
